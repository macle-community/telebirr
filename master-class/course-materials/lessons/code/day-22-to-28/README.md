# Days 22–28 — Device, polish, and release exercises

- **Day 22:** [`capability-demo.tsx`](./day-22/capability-demo.tsx) models
  available/unavailable/denied UI states; it does not call a native device API.
- **Day 23:** [`pickup-points.tsx`](./day-23/pickup-points.tsx) uses fictional
  locations only.
- **Day 24:** [`derived-filter.tsx`](./day-24/derived-filter.tsx) demonstrates
  memoized derived list data; measure before using memoization in a real page.
- **Day 25:** [`debugging-checklist.md`](./day-25/debugging-checklist.md)
  provides a repeatable diagnosis record.
- **Day 26:** [`request-state.tsx`](./day-26/request-state.tsx) presents
  explicit loading, empty, error, and success states.
- **Day 27:** [`release-checklist.md`](./day-27/release-checklist.md) is a
  manual checklist; it does not claim portal approval.
- **Day 28:** [`device-matrix.csv`](./day-28/device-matrix.csv) is a test
  record template. Mark untested device combinations as “not tested.”
